# TCS bot tools — implementation spec

The demo bot has four tools. Their JSON is generated by
`scripts/build_tcs_workflows.py`; anything that depends on the installed n8n
version (node type availability, expression scope) is marked **MANUAL** in
`HUMAN_TODO.md` and must be re-checked in the n8n UI after import.

All SQL below uses the demo tables: `tcs_leads`, `tcs_units`, `tcs_events`,
`crm_conversation_state`. `whatsapp_id` is always `tg:<chat_id>`.

## 1. search_units (Postgres tool)

Inputs from the model: `beds` (int, optional), `max_rent` (int, optional),
`pets` (bool, optional).

```sql
SELECT building, unit_number, beds, baths, rent_usd, deposit_usd,
       available_from, pets_policy, description
FROM tcs_units
WHERE status = 'available'
  AND ($1::int IS NULL OR beds = $1)
  AND ($2::int IS NULL OR rent_usd <= $2)
  AND ($3::bool IS NOT TRUE
       OR lower(pets_policy) NOT LIKE 'no pets%')
ORDER BY rent_usd
LIMIT 5;
```

Agent-facing description: “Search available apartments. Use for any question
about availability, price, or building.”

## 2. get_slots (Code tool)

Goal: 30-minute slots, Mon–Fri 09:00–17:00 `America/New_York`, not earlier
than 3 hours from now, within the next 7 days, capacity 2 viewings per slot,
return at most 3.

```js
// 30-min slots, Mon-Fri 09:00-17:00 America/New_York, >=3h ahead, next 7 days,
// capacity 2 per slot, max 3 slots. book_viewing re-checks capacity.
const tz = 'America/New_York';
const now = new Date();
const minStart = now.getTime() + 3 * 60 * 60 * 1000;
const maxEnd = now.getTime() + 7 * 24 * 60 * 60 * 1000;

function etParts(date) {
  const f = new Intl.DateTimeFormat('en-US', {
    timeZone: tz, year: 'numeric', month: '2-digit', day: '2-digit',
    hour: '2-digit', minute: '2-digit', hour12: false, weekday: 'short',
  });
  return Object.fromEntries(
    f.formatToParts(date).filter((p) => p.type !== 'literal').map((p) => [p.type, p.value]),
  );
}
// UTC instant for an ET wall-clock time (handles DST by iterating the offset).
function etToUtc(y, m, d, hh, mm) {
  let ts = Date.UTC(y, m - 1, d, hh, mm);
  for (let i = 0; i < 3; i++) {
    const p = etParts(new Date(ts));
    const got = Date.UTC(+p.year, +p.month - 1, +p.day, (+p.hour) % 24, +p.minute);
    ts += Date.UTC(y, m - 1, d, hh, mm) - got;
  }
  return ts;
}

// Occupancy hint; the authoritative check lives in book_viewing.
const used = {};
try {
  // MANUAL: verify this reference resolves inside the Code Tool on your n8n version.
  for (const item of $('Load Booked Slots').all()) {
    const key = new Date(item.json.trial_datetime).toISOString();
    used[key] = (used[key] || 0) + Number(item.json.n || 1);
  }
} catch (e) {
  // No booked-slot context available: offer slots without the hint.
}

const today = etParts(now);
const slots = [];
for (let offset = 0; offset <= 7 && slots.length < 3; offset++) {
  const p = etParts(new Date(Date.UTC(+today.year, +today.month - 1, +today.day + offset, 12)));
  if (p.weekday === 'Sat' || p.weekday === 'Sun') continue;
  for (let hour = 9; hour < 17 && slots.length < 3; hour++) {
    for (const minute of [0, 30]) {
      const ts = etToUtc(+p.year, +p.month, +p.day, hour, minute);
      if (ts < minStart || ts > maxEnd) continue;
      const key = new Date(ts).toISOString();
      if ((used[key] || 0) >= 2) continue;
      slots.push({
        slot: key,
        local: new Intl.DateTimeFormat('en-US', {
          timeZone: tz, weekday: 'short', month: 'short', day: 'numeric',
          hour: 'numeric', minute: '2-digit',
        }).format(ts),
      });
      if (slots.length >= 3) break;
    }
  }
}
return slots;
```

Agent-facing description: “Offer up to 3 viewing slots (30 min, weekdays
09:00–17:00 America/New_York, at least 3 hours ahead).”

## 3. book_viewing (Postgres tool)

Inputs: `whatsapp_id` (string), `slot` (ISO timestamptz), `direction`,
`goal`, `building`, `unit_number`.

One statement = one transaction. Re-checks capacity, then updates the lead and
writes the event. Returns `{"result":"booked"}` or `{"result":"slot_taken"}`.

```sql
WITH cap AS (
  SELECT COUNT(*) AS n FROM tcs_leads
  WHERE trial_datetime = $2::timestamptz
), upd AS (
  UPDATE tcs_leads
  SET trial_datetime = $2::timestamptz,
      current_stage = 'VIEWING_SCHEDULED',
      status = 'ЗАПИСАН',
      direction = COALESCE(NULLIF($3,''), direction),
      goal = COALESCE(NULLIF($4,''), goal),
      lead_data = CASE
                    WHEN NULLIF($5,'') IS NOT NULL AND NULLIF($6,'') IS NOT NULL
                    THEN COALESCE(lead_data, '{}'::jsonb)
                         || jsonb_build_object('unit', $5 || ' ' || $6)
                    ELSE lead_data
                  END,
      reminder_sent = false,
      last_message_at = now(),
      updated_at = now()
  WHERE whatsapp_id = $1 AND (SELECT n FROM cap) < 2
  RETURNING whatsapp_id
), ev AS (
  INSERT INTO tcs_events (whatsapp_id, event_type, payload)
  SELECT $1, 'trial_booked',
         jsonb_build_object(
           'trial_datetime', $2::timestamptz,
           'building', NULLIF($5,''),
           'unit_number', NULLIF($6,'')
         )
  WHERE EXISTS (SELECT 1 FROM upd)
)
SELECT CASE WHEN EXISTS (SELECT 1 FROM upd) THEN 'booked' ELSE 'slot_taken' END AS result;
```

## 4. handoff_to_human (Postgres tool)

Inputs: `whatsapp_id` (string), `reason` (string, optional).

```sql
WITH upd AS (
  UPDATE tcs_leads
  SET status = 'МЕНЕДЖЕР', updated_at = now()
  WHERE whatsapp_id = $1
  RETURNING whatsapp_id
), ev AS (
  INSERT INTO tcs_events (whatsapp_id, event_type, payload)
  SELECT $1, 'transferred_to_manager', jsonb_build_object('reason', NULLIF($2,''))
  WHERE EXISTS (SELECT 1 FROM upd)
)
SELECT 'handed_off' AS result;
```

The CRM mirrors this status into a deal and raises an urgent task and a
notification for managers by itself (`sync_worker` / `services/unified.py`), so
the bot does not call the CRM API.

## Notes

- `slot_taken` must be handled by the model: apologize and offer other slots.
- The reminder workflow (W-C) uses `reminder_sent` and joins `tcs_units` on
  `lead_data->>'unit'`; booking stores `building unit_number` there and resets
  `reminder_sent` to false.
- Credentials in n8n: `Postgres account` (demo DB), `Telegram account`
  (demo bot), `OpenRouter account` (model). Never commit tokens.
